# План интеграционного тестирования — практическая работа №17

## Объект и среда

Проверяется взаимодействие `EquipmentService`, `EquipmentRepository` и SQLite для приложения учета оборудования. Каждый тест создает собственный `EquipmentRepository(":memory:")`; пользовательская база приложения не открывается и не изменяется.

## Методы тестирования

- **Черный ящик:** тесты вызывают публичные методы сервиса и сверяют сохраненное состояние через публичные операции чтения.
- **Классы эквивалентности:** валидные записи; пустые обязательные поля; отрицательная стоимость; запись с существующим инвентарным номером; существующие и отсутствующие результаты поиска.
- **Граничные значения:** нулевая стоимость и текущая дата проверяются в тестах практической №16; в этой работе используются как исходные граничные примеры интеграционного потока. Параметры формулы различаются по знаку и величине.

## Сценарии

| Проверка | Взаимодействие | Ожидаемый результат |
|---|---|---|
| CRUD, поиск, ведомость и сумма | сервис → SQLite → сервис | Добавление, изменение, поиск, отчет и сумма видят одни значения; удаленная запись отсутствует |
| Перемещение и ремонт | оборудование, журнал перемещений, ремонты | Подразделение обновлено; история и ремонт связаны с тем же ID |
| Технический осмотр | запись осмотра и состояние оборудования | Осмотр и дата последней проверки доступны после сохранения |
| Некорректные данные и пустое хранилище | валидатор, сервис, SQLite | Невалидная запись не добавляется; пустые список, ведомость и сумма корректны |
| Поток трех методов | вариантный метод → создание модели → запись через сервис | Параметры `a`, `b` передаются в `CalculateC`, результат `c` попадает в стоимость и SQLite |

## Выбранная вариантная формула

По уточнению пользователя выбран вариант 5. В таблице задания (формула приведена изображением) указано `c = a³ − 3b`; табличный пример `a=5, b=16` даёт `c=77`. Вычисление реализовано в `EquipmentVariant5Workflow.CalculateC` без тестовой заглушки.

Три взаимосвязанных метода класса: `CalculateC(a,b)`, `CreateEquipment(...,a,b)` и `AddEquipment(...,a,b)`. Каждый вариантный тест один раз вызывает `AddEquipment`, проходит через все три метода, затем проверяет расчет и сохранение в SQLite.
